# 일반 체크리스트·구성품 통합 레포트 설계

## 상태와 목적

2026-09-13 사용자가 이 명세의 구현을 승인했다. 통합 기능 구현 완료나 개별 항목의 업무 승인 기록은 아니다. 직전 구현 기준은 `cd803f12d69bb1874765072e6d6f381fe9bcd95e`다.

담당자가 일반 체크리스트와 구성품 상세 결과를 Excel 하나에서 확인하도록 한다. 관찰 결과를 모으는 작업이며, 자동 합격/불합격 판정이나 DB 교체를 하지 않는다.

## 1. 실제 자료 조사

다음 완료 폴더를 기존 검증 함수로 읽었다.

- 일반 체크리스트: `outputs/review_service_zc_20260911_r2/`
- 구성품 상세: `outputs/item_review_zc_20260913_unified/`

두 결과의 PDF·semantic XML·추출 완료 기록 SHA-256 및 문서 context가 모두 같다. 폴더는 달라도 동일 문서·추출본의 결과다.

| 구분 | 확인한 값 | 의미 |
|---|---:|---|
| 기존 규칙 | 547 | 원본 DB 이관 감사 기준 |
| 상위 검토 대상 | 59 | CHK-002 구성품 부모 1건 포함 |
| 대상 아님/기존 비승인 | 488 | 삭제하지 않고 내부 감사 기록 유지 |
| 일반 근거 | 40 | 단일 근거·구조 후보·분산 문구 |
| 구성품 상세 | 14 | CHK-002-ZC-ENG의 하위 항목 |
| 구성품 근거 | 26 | 항목 문구 14개·조건 안내 후보 12개 |

기존 부모 CHK-002는 `needs_review / not_examined / unsupported_selector`다. 하위 문구 14개를 찾았더라도 모델 적용과 전체 요구사항을 검사한 것은 아니므로 부모를 합격으로 바꿀 수 없다.

## 2. 방식 비교

1. **새 통합 표시 데이터 → Excel 하나 — 추천.** 기존 JSON들을 검증하고 묶는다. 추출·DB를 변경하지 않으며 출처 혼용과 중복 집계를 검사할 수 있다.
2. 기존 Excel의 시트만 복사한다. 빠르게 보이지만 중복 요약과 오래된 결과의 혼용을 별도로 막아야 한다.
3. DB와 검토 엔진까지 한 번에 교체한다. 조건 승인과 판정 구현까지 얽히므로 이번 단계에서 하지 않는다.

## 3. 집계 계약

**상위 체크리스트 59건과 그중 구성품 상세 14건을 별도로 표시한다.** 73건으로 합산하지 않고, 부모를 제거해 72건으로 바꾸지도 않는다.

- Checklist Results에 기존 59행 유지.
- CHK-002 부모 행에는 `구성품별 근거는 Item Results 참조` 안내 추가. 원본 관찰/설명은 JSON에 보존.
- Item Results에 하위 14행 유지. 부모 관계는 `parent_check_id=CHK-002-ZC-ENG`로 명시.
- 상위·하위 모두 검토 필요 상태 유지. 발견 수는 합격 수가 아님.
- 나머지 항목 분리 후보를 임의로 분리하거나 DB에 활성화하지 않음.

## 4. 사용자 산출물 계약

새 통합 폴더에 사용자용 `review_report.xlsx`, 내부 `review_report.json`, 표시용 `review_report_view.json`, 완료 기록 `review_report_complete.json`을 저장한다. 과거 폴더는 수정/삭제하지 않는다.

첫 구현은 이미 검증된 결과 두 개를 읽는 개발용 명령으로 제한한다. PDF 재추출 없이 새 통합 폴더 하나에 결과를 만든다. 담당자에게 두 폴더를 입력하는 새 화면은 만들지 않는다. 단일 PDF 실행과 조회 화면 연결은 다음 단계다.

| 시트 | 사용 목적 |
|---|---|
| Summary | 대상 PDF와 상태, 상위 59건/구성품 상세 14건을 구분 |
| Checklist Results | 기준 문구·현재 원문·검토 판정·설명·페이지·메모, 기존 59행 |
| Item Results | 현재 구성품 14행의 열/값/검토 메모 구성 유지 |
| Source Evidence | 일반 40행과 구성품 26행의 근거를 구분해 보존 |

Summary는 머리글 포함 12행 이내다. 데이터 11행은 PDF 파일명, 프로필, 검토 언어, 검토 상태, 상위 체크리스트 수, 구성품 상세 수, 구성품 단일 문구 근거 수, 구성품 조건 안내 후보 수, 상세 근거 행 수, 대상 아님/기존 비승인 수, 메모 사용 안내로 정한다. 내부 해시·경로·원장 과거 출처는 JSON에만 둔다.

기존 제외 488행과 원본 규칙 547행은 내부 JSON에 유지한다. 사용자 Excel에 별도 감사 시트를 늘리지 않는다. 아직 구현하지 않은 Diff/Model Spec/표지·이미지 비교도 빈 시트로 만들지 않는다.

## 5. 근거 연결

Source Evidence는 임시 E0001 번호 대신 `체크 ID + 고정 항목 키 + 근거 종류`로 연결한다.

- 일반 근거: 체크 ID 있음, 고정 항목 키는 빈 값.
- 구성품 근거: 부모 체크 ID와 고정 항목 키 모두 있음.
- 종류: 일반 문구/구조 후보/분산 문구/구성품 문구/조건 안내 후보 구분.
- 원문·XML 노드 ID·태그·PDF 페이지·XML 경로·상세 근거 보존.
- 같은 조건 안내가 여러 구성품에 연결되므로 근거 66행을 임의 중복 제거하지 않음.
- 항목 키는 부모 아래에서 식별하며, 이번 구현은 검증된 부모 1개만 지원.

실물 구현 조정: 일반 근거의 상세 JSON 셀에는 전체 노드별 근거와 조합 방식·언어·분산 기준 문구·그림 연결·주의사항을 보존한다. 옆 열에 이미 표시한 원문·노드·태그·페이지·경로를 JSON 셀 안에 다시 반복하지 않는다. MCID/object reference는 노드별 근거 안에 그대로 있다. 일반 XML 경로 목록은 줄바꿈 대신 `; `로 구분하고 JSON 공백만 압축한다. 원본 관찰은 내부 통합 JSON에 변경 없이 보관한다. Excel 행 높이 한도를 맞추기 위한 중복 표시 제거이며 원문 축약이나 근거 행 삭제가 아니다.

현재 원장 제안은 기존 Item Results 열에 유지하고 자동 실행하지 않는다. 메모는 결과 사본의 의견이며 DB 승인 입력이 아니다.

## 6. 내부 흐름과 안전 기준

`완료된 일반 관찰 + 완료된 항목 관찰 → 통합 JSON → 표시 데이터 → Excel`로 구성한다. Markdown이나 기존 Excel을 원문 입력으로 파싱하지 않는다.

책임은 입력 검사, 통합 보고서 데이터, 행·열 표시 변환, Excel 작성/검증으로 나눈다. 파일은 현재 flat src 구조를 따른다. 통합 JSON은 원본 두 관찰을 무손실로 포함하고 부모·하위 연결과 분리 집계만 추가한다.

최초 호환 조건은 양쪽의 PDF/semantic XML/추출 완료 기록 해시 및 context 전체 일치다. 동일 파일명만으로 합치지 않고, 경로 문자열 자체의 일치를 요구하지 않는다. 다른 추출 실행을 자동으로 동등하다고 추정하지 않는다.

부모는 현재 프로필에서 needs_review인 CHK-002-ZC-ENG 1행이어야 한다. 하위는 검증된 14개 고정 키와 원문을 유지해야 한다. 부모 누락·중복·비대상, 자동 판정이나 원장 활성화가 들어간 결과는 거절한다.

통합 시에는 XML·추출 완료 자료를 실제로 열어 양쪽 근거의 노드·태그·페이지·경로를 검증한다. 통합 JSON에 원본 관찰과 검증된 출처/노드 자료를 포함한다. 완료된 통합 결과의 재조회에는 과거 PDF/DB 경로의 존재를 요구하지 않고 자체 보관 자료와 완료 기록을 검증한다.

출력 폴더가 이미 있으면 덮어쓰지 않는다. 읽은 입력과 생성 출력의 전후 변경을 검사하고, JSON/Excel 검증 뒤 완료 기록을 마지막에 게시한다. 실패 폴더는 진단용으로 보존하며 정상 다운로드에 제공하지 않는다.

새 통합 경로는 HTML을 생성하거나 다운로드하지 않는다. 과거 일반 관찰 v1을 읽을 때만 기존 HTML 해시를 확인한다. 기존 run_review의 HTML 생성 정책 자체는 별도 변경하지 않는다.

## 7. 구현 완료 검증 기준

- 실제 ZC 통합 결과의 상위59/하위14/일반근거40/항목근거26/내부제외488/원본규칙547 보존.
- 원본 JSON·DB 해시 불변, 부모 결과 유지, 자동 pass/fail 없음.
- 동일 파일명 다른 PDF, 다른 XML/완료 기록/context, 부모 누락·중복·비대상, 항목 키 중복 거절.
- 분산 문구를 전체 일치로 합치지 않음. 조건 후보·원장 제안을 승인으로 바꾸지 않음.
- 입력/출력 변경, 부분 저장, 재실행 충돌 방어.
- Excel 전 셀 대조·렌더 검수. 긴 문자열 자르기, 수식 실행, 외부 링크/매크로 금지.
- 현재 단독 item_review.xlsx와 단일 폴더 조회 기능 회귀 없음.
- 집중 테스트·루트 전체 테스트·compileall 실행. 별도 XML POC 전체 suite는 실행 여부를 별도 기록.

## 8. 후속 순서와 범위

1. 이 명세 확인 → 구현 계획 → 통합 JSON/Excel 및 실제 ZC 검증.
2. 단일 폴더 조회/다운로드 연결, 한 번의 PDF 추출 결과를 두 관찰이 공유하는 실행 명령 연결.
3. 담당자 PC용 작성기·의존성·설치/실행 명령 정리. 개발용 Artifact Tool 환경이 각 PC에 있다고 가정하거나 사유 런타임을 임의 복제하지 않음.
4. 별도의 원문 대조/업무 정의 후 다른 항목·바이어와 조건별 evaluator 확대.

전체 PC 배포와 자동 업무 판정은 이번 표시 통합의 완료 기준에 포함하지 않는다.
