# Semantic XML → Markdown 변환 설계

## 목적

`semantic_document.xml`을 비개발자가 읽고 검토하기 쉬운 단일 Markdown 문서로 변환한다. 변환 결과는 원본 PDF에서 추출된 영어와 프랑스어의 등장 순서를 유지하며, 문장 연결·제목 계층·목록·표·OSD 경로와 특수문자 보존 여부를 사람이 빠르게 확인할 수 있어야 한다.

## 선택한 방식

검토 대상은 `raw_structure.xml`이 아니라 `semantic_document.xml`이다. Raw XML은 원본 태그와 MCID를 조사하는 개발자용 근거 자료로 유지하고, Markdown은 Semantic XML의 읽기 좋은 구조를 표현한다.

영어와 프랑스어는 별도 파일로 분리하지 않고 PDF의 추출 순서 그대로 하나의 파일에 기록한다. 이 방식은 언어 경계와 전체 문서 순서가 변환 과정에서 바뀌지 않았는지 확인하기 쉽다.

PDF의 `/RoleMap`이 제목 역할을 일반 문단 `P`로 연결했기 때문에 Semantic XML만으로는 38개 제목 후보를 식별할 수 없다. 따라서 변환기는 같은 출력 묶음의 `extraction_report.json`에 있는 `heading_hierarchy`를 함께 읽는다. `classification=source_role_candidate`인 항목을 검토용 제목으로 승격하고, 후보의 `level`을 Markdown 제목 단계에 반영한다.

## 변환 규칙

- 출력 파일명: `semantic_document.md`
- 최상단에 원본 파일명, 변환 목적, 제목이 PDF 원본 역할명에 기반한 후보라는 주의문을 기록한다.
- `heading_hierarchy`의 구조 경로와 Semantic XML 요소 경로를 대응시켜 제목 후보를 `#` 계열 제목으로 출력한다.
- 문서 자체의 안내 제목을 `#`으로 사용하므로 PDF 제목 후보 레벨 1은 `##`, 레벨 2는 `###`처럼 한 단계 내려서 표시한다.
- 일반 문단은 내부의 여러 `<text>` 조각을 읽기 순서대로 합쳐 하나의 문단으로 출력한다.
- 목록은 Markdown 글머리표로 출력하고, 중첩 목록은 들여쓰기로 보존한다.
- 단순한 행·열 구조의 표는 Markdown 표로 출력한다. 병합 셀, 중첩 표 또는 불균일한 행처럼 Markdown 표가 정확히 표현하지 못하는 경우에는 행별 목록으로 내려쓰되 내용을 버리지 않는다.
- 링크, 괄호, `>`, `/`, `:`, `&`, 대괄호 등 원문 특수문자는 의미가 바뀌지 않도록 보존한다. Markdown 문법으로 오해될 문자만 필요한 범위에서 이스케이프한다.
- `<control code="..."/>`는 숨기지 않는다. 사람이 문제 구간을 확인할 수 있도록 `[CONTROL U+XXXX]` 표기로 바꾼다.
- 그림에 추출 가능한 대체 텍스트가 없으면 `[그림: 텍스트 없음]`으로 표시한다.
- XML 속성, MCID, object reference, BBox 같은 개발자용 정보는 본문에 노출하지 않는다.

## 구성 요소

변환 기능은 기존 PDF 추출과 분리된 작은 모듈로 둔다.

1. XML/리포트 로더: Semantic XML과 JSON을 검증해 읽는다.
2. 구조 경로 계산기: 리포트의 제목 후보 경로와 XML 요소를 정확히 대응시킨다.
3. Markdown 렌더러: 제목, 문단, 목록, 표, 그림을 Markdown으로 변환한다.
4. 출력 작성기: 임시 파일에 쓴 뒤 검증에 성공하면 `semantic_document.md`로 교체한다.
5. CLI 연결: 기존 추출 명령 실행 시 XML·JSON과 함께 Markdown을 자동 생성한다.

## 오류 처리

- Semantic XML 또는 리포트가 없거나 파싱되지 않으면 Markdown을 만들지 않고 명확한 오류를 반환한다.
- 제목 후보 경로가 XML 요소와 일치하지 않으면 일반 문단으로 보존하고 경고를 기록한다. 텍스트를 삭제하거나 임의의 제목으로 바꾸지 않는다.
- 표를 Markdown 표로 안전하게 표현할 수 없으면 행별 목록으로 대체한다.
- 기존 결과를 덮어쓰는 동작은 현재 출력 묶음의 원자적 저장 정책을 따른다.

## 검증 기준

- 문단에 흩어진 `<text>`가 순서대로 합쳐진다.
- 알려진 OSD 경로가 끊기거나 변형되지 않는다.
- 제목 후보 38개가 리포트와 같은 텍스트·순서·레벨로 나타난다.
- 영어와 프랑스어의 전체 순서가 Semantic XML과 같다.
- 목록과 표의 모든 텍스트가 Markdown에 남는다.
- XML 제어문자 608개가 누락되지 않고 표시된다.
- 변환 전후의 사람이 읽을 수 있는 텍스트를 비교해, Markdown 문법 문자와 명시적 대체 표기를 제외한 본문 손실이 없음을 자동 검사한다.
- 기존 XML 및 JSON 출력 내용은 바뀌지 않는다.

## 범위 제외

이번 단계에서는 번역, OCR, 이미지 삽입, 영어·프랑스어 파일 분리, 손상된 PDF 문자 자동 교정, 제목 후보의 진위 판정은 수행하지 않는다. Markdown은 추출 결과를 읽기 쉽게 보여주는 검토 자료이며 XML과 JSON이 근거 자료로 남는다.
