# 항목별 검토와 출처 표시 설계

## 상태와 범위

2026-09-11 사용자 피드백 반영. item별 DB 검토 단위 설계는 진행 승인됐고, 원본 PDF 파일명을 출처 상단에 한 번 표시하는 방향을 채택한다. `observation`/`reason` 중복 문제에 대해서는 아래 두 열 표시를 권고안으로 기록한다. 이는 개별 항목의 업무 승인이나 최종 Excel 실물 승인과 다르다.

이번 문서는 설계 기록이다. 기존 Excel 초안, 실행 코드, 동결 DB는 아직 변경하지 않는다. 기존 초안의 547행/59개 적용 수는 분리 이전 기준이며 새 항목 수와 직접 비교하지 않는다.

## 1. 사용자용 결과는 판정과 설명

세 열을 모두 사용자에게 노출할 필요는 없다. 일반 결과는 `검토 판정`과 `설명` 두 열로 구성하는 것을 권한다.

- 검토 판정: 이번 문서에 대해 실제로 내린 판정. 현재 관찰 단계는 `검토 필요`이며 근거 발견을 합격으로 바꾸지 않는다.
- 설명: 관찰 상태와 사유를 합쳐 한 문장으로 전달한다. 예: `문구는 찾았지만 적용 조건은 아직 검사하지 않았습니다.`, `서로 다른 XML 문단에 나뉜 근거를 찾았습니다.`, `표 전용 검사를 지원하지 않아 확인하지 못했습니다.`
- `observation`은 별도 일반 결과 열에서 빼되 JSON의 진단 코드와 근거 종류는 보존한다. `reason` 원시 코드도 그대로 사용자에게 중복 표시하지 않는다.
- 단순히 observation을 삭제하고 기존 reason만 보여주면 발견/분산/미지원 차이가 사라질 수 있다. 표시 변환에서 두 정보를 함께 해석한다.
- 미지원, 근거 미발견, 추출 실패를 모두 `누락`으로 표현하지 않는다. 설명 조합으로도 자동 판정이 생기면 안 된다.

## 2. 출처는 보고서 단위, 노드는 해당 추출본 안에서 식별

체크리스트 항목 ID는 요구사항을 식별하는 고정 키다. XML 노드 ID는 해당 추출본의 위치 키다. 같은 PDF와 같은 추출 구조이면 재실행해도 같을 수 있으나, PDF 수정이나 구조/추출기 변경 뒤에도 같다고 보장하지 않는다.

단일 문서 보고서의 Summary에 출처 패널을 한 번 둔다:

- 원본 PDF 파일명.
- 확인에 사용할 추출 결과 폴더 또는 보관된 XML 파일 위치.
- 추출본 식별 정보: 검증된 PDF SHA256와 semantic XML SHA256. 파일명은 같아도 내용이 다른 경우를 구분한다.
- 사용한 추출 완료 기록의 참조. 해시/참조는 기존 검증 receipt에서 가져오고 파일명으로 추측하지 않는다.

파일명은 사람이 찾기 위한 정보이고 해시는 프로그램이 정확한 파일을 구별하기 위한 정보다. 사용자가 해시를 직접 입력하거나 판독할 필요는 없다.

각 근거 행에는 노드 ID, 태그 종류, 페이지를 둔다. 상세 근거에는 원문, 전체 XML 경로, 존재하는 MCID/object-ref, 관련 그림의 노드 ID를 보존한다. 없는 참조를 만들어 내지 않는다. 태그 종류나 MCID 단독을 전역 고유 키로 취급하지 않는다.

현재 `evidence_id`는 보고서 근거 행 번호이므로 XML 노드 ID와 구분해 표시한다. 문장/그림이 이미 영구적인 고유 ID를 가진다고 가정하지 않는다. 이후 다중 문서 비교 시에는 출처 패널에 문서별 source ID를 부여하고 각 근거 행이 해당 출처를 가리키도록 확장해야 한다.

## 3. item별 DB 검토 단위

`CHK-002` 구성품 묶음을 유지하면서 독립적으로 확인할 하위 항목을 정의한다. Excel에서만 줄을 나누는 것이 아니라 검사 대상 자체를 나눈다. 기존 `check_id`는 이관 출처로 보존하며 XML 위치나 현재 행 순서를 새 영구 항목 ID로 사용하지 않는다.

하위 항목 초안에는 기존 check_id, 고정 하위 항목 키, 원문 기준 문구, 기존 적용/제외 범위, 확인된 조건, 근거 참조, 이관 검토 상태를 둔다. 구체 키 목록과 실제 조건은 원문 대조 후 확정한다. 기존 승인 문구를 가져왔다고 새 항목의 적용 조건까지 승인된 것으로 취급하지 않는다.

첫 대상 `CHK-002-ZC-ENG`의 기존 14줄을 후보 출발점으로 삼는다. 줄마다 반드시 독립 요구사항이라는 뜻은 아니다.

- `Warranty Card / Regulatory Guide (Not available in some locations)`의 괄호 조건은 항목에 붙여 보존한다.
- `Wall Mount Adapter x 2`, `Power Box Cable x 2`의 수량은 보존한다.
- 리모컨 종류와 모델/지역 조건은 모두 무조건 필수라고 가정하지 않고 실제 문서 관계를 확인한다.
- 관련 그림은 자동으로 의미를 붙이지 않고 원문 위치와 관계를 근거로 남긴다.
- 언어별 문장 수를 맞추지 않는다. 같은 검사 항목에 여러 문장/노드를 연결할 수 있다.
- 개별 결과와 상위 묶음 집계는 구분한다. 항목의 적용 조건을 확정하기 전에는 전체 합격 집계를 구현하지 않는다.

## 4. 이어서 진행할 작업과 검증 기준

1. 기존 DB를 읽기 전용으로 분류한다: 유지 / 항목 분리 후보 / 표 관계 검사 / 조건부 적용 / 판단 보류. 한 행에 분류가 여러 개 적용될 수 있다.
2. CHK-002의 기존 행과 신규 하위 항목 대응 초안을 작성하고, 문구/수량/조건/범위/출처를 빠짐없이 대조한다. 다른 언어는 확인한 원문만 사용한다.
3. 원본 Excel은 보존하고 새 v2 Excel 초안에서 확정된 구조를 관리한다. JSON은 Excel에서 내보내며 직접 수정하지 않는다.
4. 항목별 검사와 결과 표시를 연결한다. 표시 전용 테스트는 판정 불변, 관찰/사유 설명 보존, 노드/페이지 추적, 동일 파일명 다른 추출본 구분을 확인한다.
5. 항목 분리 테스트는 원문 무손실, 중복/누락 없음, 조건/수량 보존, 고정 키와 XML 키 분리, 자동 승인 없음, 상위/하위 집계의 중복 없음과 다국어 다대다 근거 연결을 확인한다.

기존 PDF→XML→ReviewDocument 연결을 다시 만들 필요는 없다. 다음 중심 작업은 업무 검토 단위 정의이며, 그 결과에 맞춰 표시용 변환과 출력기를 바꾼다.
