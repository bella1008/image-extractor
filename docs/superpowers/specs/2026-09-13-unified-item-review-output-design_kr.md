# 항목 검토 결과 단일 폴더·사용자 중심 Excel 설계

## 목적

PDF 한 건을 검토한 담당자가 여러 결과 폴더와 중복 파일 사이에서 최종 결과를 찾지 않도록 한다. 검토 결과 생성과 Excel 표현 코드는 계속 분리하지만, 사용자가 받는 산출물은 실행 폴더 하나에 모은다.

이 변경은 CHK-002-ZC-ENG 하위 14개 항목 파일럿에 적용한다. 체크리스트 판정, XML 추출 규칙, ReviewDocument, 기존 DB는 변경하지 않는다.

## 선택한 방식

검토 결과와 Excel을 별도 폴더에 저장하는 현재 방식 대신, **하나의 실행 폴더에 내부 자료와 사용자용 Excel을 함께 저장**한다.

```text
PDF → XML → ReviewDocument → 항목별 관찰 결과 JSON
                                ↓
                         같은 폴더에 Excel 생성
```

새 실행의 결과는 다음과 같다.

```text
문서명_검토일시/
├─ item_review.xlsx
├─ item_observation.json
├─ item_review_complete.json
├─ item_excel_complete.json
├─ item_excel_view.json
└─ extraction/
```

사용자가 확인할 파일은 `item_review.xlsx` 하나다. JSON과 완료 기록은 입력 변경, 부분 저장, 다른 실행 결과 혼용을 막기 위한 내부 자료다. `extraction/`에는 XML, ReviewDocument와 추출 완료 기록이 있다.

코드에서는 관찰 결과 생성과 Excel 생성을 계속 별도 단계로 유지한다. Excel 양식만 바꿀 때 PDF/XML 처리를 다시 할 필요가 없기 때문이다. 단, 두 단계의 출력 위치는 동일하다.

## HTML 처리

새 실행에서는 `item_review.html`을 만들지 않는다. HTML은 Streamlit 화면 이전의 임시 확인 수단이었고, 현재는 Excel과 로컬 화면에 역할이 중복된다.

- 새 완료 기록의 필수 관찰 산출물은 `item_observation.json` 하나다.
- Streamlit은 JSON과 같은 폴더의 검증된 Excel만 읽는다.
- 화면의 HTML 다운로드 버튼을 제거한다.
- 기존 실행 폴더의 HTML은 삭제하지 않는다.
- 과거 완료 기록이 JSON과 HTML을 함께 기록한 경우에는 읽기 호환만 유지한다. 새 HTML을 다시 만들거나 사용자에게 노출하지 않는다.

## Excel 사용자 계약

### Summary

사용자에게 필요한 현재 상태와 집계, 대상 PDF 파일명까지만 표시한다. 기존 파일의 13행인 `PDF SHA256`부터 아래 행은 모두 제거한다.

표시 내용은 다음 11개 데이터 행과 머리글이다.

1. 부모 체크항목
2. 상태
3. 검토 메모 사용 안내
4. 하위 항목 수
5. 단일 문구 근거 수
6. 복수 근거 수
7. 검색 범위 내 미발견 수
8. 범위 미확정 수
9. 검토 필요 수
10. 조건 안내 연결 후보 수
11. 검토 대상 PDF 파일명

PDF/XML/완료 기록 해시, 추출 경로, 원장 작성 당시 출처는 `item_observation.json`과 완료 기록에 그대로 유지한다. Excel에서만 제외한다.

### Item Results

`항목 근거 ID`와 `조건 후보 ID`를 제거한다. 이 값은 `E0001`처럼 Excel 생성 순서대로 붙인 보고서 내부 임시 번호였으며, DB 키·XML 노드 ID·고정 근거 ID가 아니다. 근거 순서가 달라지면 바뀔 수 있어 사용자에게 안정적인 의미를 주지 못한다.

항목은 `고정 항목 키`로 식별한다. 담당자는 판정, 설명, 검토 메모와 원장 제안 이력을 확인한다.

### Source Evidence

`근거 ID`를 제거하고 `고정 항목 키`와 `근거 종류`로 Item Results와 연결한다. 한 항목에 근거가 여러 개면 동일한 고정 항목 키의 행이 여러 개 생긴다. 현재 원문, XML 노드 ID, 태그, PDF 페이지, XML 경로와 상세 근거 JSON은 유지한다.

항목과 근거의 실제 관계는 `item_observation.json`의 항목별 중첩 구조가 보존하므로 임시 `E####` 번호가 없어도 정보 손실이 없다.

## 화면 계약

화면에는 결과 폴더 입력칸 하나만 둔다. 별도 Excel 폴더 입력칸은 제거한다.

- 폴더를 불러오면 검증된 JSON 결과를 표시한다.
- 같은 폴더에 완료된 Excel이 있으면 Excel 다운로드를 제공한다.
- Excel이 아직 없으면 결과는 표시하되 `Excel이 아직 생성되지 않음`을 알린다.
- JSON과 Excel 다운로드만 제공한다. HTML 다운로드는 제공하지 않는다.
- 파일이 변경되거나 완료 기록이 맞지 않으면 오래된 결과나 다운로드를 표시하지 않는다.

## 기존 결과와 새 결과

기존 `outputs/item_review_zc_20260911_reuse_r2`와 `outputs/item_excel_zc_20260911_r2`는 삭제하거나 덮어쓰지 않는다. 과거 검증 결과로 그대로 보존한다.

변경된 계약의 실물 검증은 새로운 결과 폴더에 생성한다. 그 폴더 안에서 JSON과 Excel이 함께 존재하는지, Summary가 12행(머리글 포함)인지, 사용자 Excel에 `E####` 임시 ID가 없는지 확인한다.

## 오류 처리와 검증

- 기존 파일과 이름이 충돌하면 덮어쓰지 않고 실패한다.
- 관찰 결과가 완료되지 않았거나 저장 중 변경되면 Excel 완료 기록을 만들지 않는다.
- Excel 저장 후 전체 셀 값, 시트 순서, 필터, 고정창, 수식·외부 링크 부재를 검사한다.
- 실제 Excel 세 시트를 렌더링해 글자 잘림과 불필요한 내부 정보 노출을 확인한다.
- 신규 실행의 HTML 미생성, 과거 HTML 실행 읽기 호환, 단일 폴더 화면 로드와 다운로드를 회귀 테스트한다.
- 전체 테스트와 `compileall`을 실행한 뒤 별도 Git 복구 기준점을 저장한다.

## 이번 범위 밖

- 일반 체크리스트와 Item Results를 최종 Excel 하나로 합치는 작업
- PDF 업로드와 검토 실행 버튼 연결
- 다른 바이어와 나머지 item-list 항목 확장
- 모델 적용 승인과 DB 편집
- 과거 결과 폴더 삭제 또는 자동 변환

향후 최종 결과 Excel이 확정되면 `Item Results`와 `Source Evidence`를 그 파일의 시트로 편입한다. 이번 변경은 이를 쉽게 할 수 있도록 사용자용 시트 계약을 정리하는 단계다.
