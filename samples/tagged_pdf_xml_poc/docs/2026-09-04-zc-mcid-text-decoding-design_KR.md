# ZC MCID 텍스트 디코딩 개선 설계

작성일: 2026-09-04  
대상 프로젝트: `samples/tagged_pdf_xml_poc`  
기준 PDF: `BN68-25100B-00_SUG_Y26 TV ALL_ZC_L02_260122.0.pdf`

## 1. 목표

태그 PDF를 직접 입력받아 PDF 구조 트리와 MCID 연결을 유지하면서 ENG와 C-FRA 텍스트를 손실 없이 추출한다.

이번 단계의 완료 범위는 다음과 같다.

- ZC ENG/C-FRA의 MCID별 텍스트 디코딩 정상화
- C-FRA에서 발생한 XML 금지 제어문자 제거
- 헤딩, 목록, 표 소속과 읽기 순서 유지
- `raw_structure.xml`, `semantic_document.xml`, `semantic_document.md`, `extraction_report.json` 재생성
- ZC 통합검사와 ZA/ZG 회귀검사

검토용 Excel의 컬럼 및 스키마 재정의는 이번 범위에 포함하지 않는다. XML/MD 추출이 안정된 다음 별도 설계한다.

## 2. 확인된 현상

현재 `McidTextCollector`는 `pypdf`의 `extract_text()` 방문자 API를 사용한다. MCID 경계에서 텍스트 버퍼를 비우기 위해 `BMC`, `BDC`, `EMC` 앞에 항등 `cm` 연산을 삽입한다.

이 경계 처리를 사용한 실제 ZC 결과는 다음과 같다.

| 페이지 | 언어 | MCID 텍스트 항목 | 추출 문자 | XML 금지 제어문자 |
| --- | --- | ---: | ---: | ---: |
| 1 | ENG | 905 | 21,978 | 0 |
| 2 | C-FRA | 951 | 27,476 | 608 |

C-FRA 제어문자 608개의 분포는 `U+0001` 4개, `U+0002` 126개, `U+0003` 285개, `U+0004` 50개, `U+0007` 52개, `U+0008` 89개, `U+000E` 1개, `U+0011` 1개다.

항등 `cm` 삽입을 제거하면 두 페이지 모두 제어문자가 0개가 되지만 C-FRA의 MCID 텍스트 항목이 647개, 추출 문자가 22,188자로 감소한다. 따라서 현재 경계 처리를 단순히 제거하는 것은 허용하지 않는다.

일반 페이지 단위 `pypdf.extract_text()`와 PyMuPDF 추출에서는 ENG/C-FRA 모두 제어문자가 0개다. 손상은 XML 또는 Markdown 작성 단계가 아니라 MCID별 분할을 위해 삽입한 경계 처리와 `pypdf` 디코딩의 상호작용에서 발생한다.

페이지별 글꼴 차이는 다음과 같다.

- ENG: TrueType + `WinAnsiEncoding`
- C-FRA: 위 글꼴에 Type0 + `Identity-H` 복합 글꼴 추가

`Ł`와 `Œ`도 경계 처리를 사용할 때만 나타나며 구조 트리의 `<label>`에 속한다. 이 PDF에서는 각각 상위 목록과 하위 목록의 불릿 글리프가 잘못 디코딩된 값이다.

## 3. 선택한 해결 방식

PDF 콘텐츠 스트림의 문자 표시 연산을 MCID 문맥 안에서 직접 수집하는 방식을 사용한다.

핵심 원칙은 다음과 같다.

1. `BMC`/`BDC`에서 MCID 스택을 열고 `EMC`에서 닫는다.
2. `Tf` 등 텍스트·글꼴 상태를 콘텐츠 스트림 순서대로 유지한다.
3. `Tj`, `TJ`, 작은따옴표, 큰따옴표 문자 표시 연산을 실행 시점의 글꼴/CMap으로 디코딩한다.
4. 디코딩된 문자열을 현재 활성 MCID에 즉시 귀속한다.
5. 콘텐츠 스트림에 가짜 `cm` 연산을 삽입하지 않는다.
6. 구조 트리는 기존 `TaggedPdfReader`가 유지하고, 새 수집기는 MCID별 텍스트만 제공한다.

이 방식은 페이지 전체 텍스트를 사후에 문장 유사도로 MCID에 재배치하는 방식보다 복잡하지만, 문장이 반복되거나 표가 있는 PDF에서도 구조 연결을 결정적으로 유지할 수 있다.

## 4. 구성요소 경계

### MCID 텍스트 수집기

- 입력: PDF 페이지, 페이지 인덱스
- 출력: `MCID -> 텍스트 조각 목록`, 발견된 MCID, 진단 목록
- 책임: 콘텐츠 스트림과 글꼴 상태를 따라 MCID별 텍스트를 복원
- 비책임: 헤딩 분류, 문장 연결, Markdown 표현

### 구조 트리 리더

- 기존 `/StructTreeRoot` 순회와 역할 매핑을 유지한다.
- MCID 번호를 새 수집기의 결과와 연결한다.
- 기존 공개 모델과 XML 작성기 계약을 변경하지 않는다.

### 목록 정규화

- 원본 XML은 source role, `<label>`, MCID 및 디코딩된 글리프를 근거로 보존한다.
- Semantic XML/Markdown은 목록 구조 자체를 사용해 불릿 계층을 표현한다.
- 특정 문자 `Ł`/`Œ`를 문서 전체에서 무조건 삭제하는 규칙은 만들지 않는다.

### 품질 평가

- XML 금지 제어문자 수를 하드 게이트로 유지한다.
- MCID 해결 실패 및 알려진 텍스트 손실 진단을 하드 게이트로 유지한다.
- ENG와 C-FRA를 페이지/언어별로 구분해 결과를 보고할 수 있어야 한다.

## 5. 고려했지만 선택하지 않은 방식

### 페이지 전체 텍스트 사후 정렬

정상적인 페이지 텍스트를 얻기는 쉽지만, 반복 문장·표·여러 열에서 MCID 경계를 잘못 추정할 수 있어 주 방식으로 사용하지 않는다.

### 제어문자와 깨진 글자 치환표

`[CONTROL U+...]`만 삭제하거나 `Ù -> f` 같은 치환을 적용하면 문맥별 원래 글자를 보장할 수 없다. 증상만 감추므로 사용하지 않는다.

### OCR

현재 PDF는 텍스트 레이어와 태그 구조를 갖고 있다. OCR은 계층과 정확한 문자를 잃을 수 있으므로 이번 문제의 해결 방식으로 사용하지 않는다.

### Acrobat XML 필수 전처리

파일이 특정 시기에 대량 유입되므로 작업자의 수동 변환을 필수 단계로 만들지 않는다. 향후 예외 진단용 비교 자료로만 사용할 수 있다.

## 6. 오류 처리

- 지원하지 않는 글꼴/연산이 발견되면 해당 MCID, 페이지, 글꼴명, 연산자를 진단에 기록한다.
- 디코딩 실패를 빈 문자열이나 임의 치환으로 숨기지 않는다.
- 새 방식이 기존보다 MCID 범위를 적게 수집하면 출력을 성공으로 판정하지 않는다.
- 문자 보존은 제어문자와 오염 글자가 포함된 기존 총문자 수가 아니라, 제어문자가 없는 페이지 단위 기준 텍스트와 내용·순서를 비교해 판정한다.
- Form XObject 안의 태그 텍스트는 기존 `tagged_form_xobject_unsupported` 진단을 유지하고 별도 범위로 보고한다.

## 7. 테스트 및 완료 기준

### 실패 재현 테스트

- ZC C-FRA Type0/Identity-H 텍스트가 현재 경계 처리에서 깨지는 사례를 고정한다.
- 단위 테스트에서는 작은 합성 콘텐츠 스트림으로 MCID 전환과 글꼴 전환을 재현한다.
- 실제 ZC PDF 통합 테스트는 샘플이 있을 때 실행한다.

### 필수 완료 기준

- ZC C-FRA `forbidden_xml_control_count == 0`
- ZC ENG `forbidden_xml_control_count == 0` 유지
- `unresolved_mcid_count == 0`
- 현재 확인된 ENG/C-FRA MCID 범위를 누락하지 않음
- 제어문자가 없는 페이지 단위 기준 텍스트와 비교했을 때 의미 있는 문자와 문장 순서를 누락하지 않음
- 프랑스어 악센트와 아포스트로피가 정상적으로 추출됨
- 알려진 C-FRA 손상 문장들이 페이지 단위 기준 텍스트와 일치함
- OSD 경로가 끊기지 않고 보존됨
- 목록의 상하위 계층이 Markdown에서 정상 표현됨
- 전체 단위 테스트와 `python -m compileall src tests` 통과
- ZA와 ZG 샘플에서 새 제어문자, MCID 손실 또는 구조 회귀가 발생하지 않음

## 8. 구현 순서

1. ZC C-FRA 실패를 고정하는 테스트 작성
2. MCID 수집기와 구조 리더의 현재 계약을 테스트로 고정
3. 가짜 `cm` 삽입 없이 문자 연산을 수집하는 디코더 구현
4. Type0/Identity-H 및 TrueType/WinAnsi 테스트 통과
5. 목록 label 정규화 테스트 및 구현
6. ZC 전체 산출물 재생성 및 품질 게이트 확인
7. ZA/ZG 회귀검사
8. 결과 문서와 README 갱신

## 9. 모델 및 중단 기준

구현은 `GPT-5.6 Sol`, reasoning `medium`을 기준으로 진행한다.

다음 중 하나가 발생하면 임의의 우회 수정을 계속하지 않고 작업을 중단해 사용자에게 모델 변경 또는 설계 재검토를 요청한다.

- 동일한 근본 원인에 대한 수정 시도가 3회 실패
- 직접 연산 디코더가 예상보다 넓은 PDF 명세 구현을 요구
- ZC를 고치면서 ENG 또는 다른 레이아웃의 MCID 구조가 반복적으로 회귀
- 서로 다른 디코딩 접근법의 선택에 사용자 판단이 필요한 경우

첫 상향 선택은 같은 모델의 reasoning `high`다. Mini로의 변경은 반복적 테스트·문서 작업에만 고려한다.
