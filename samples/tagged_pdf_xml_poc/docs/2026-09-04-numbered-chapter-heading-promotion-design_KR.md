# 번호형 장 제목 승격 설계

작성일: 2026-09-04
대상 프로젝트: `samples/tagged_pdf_xml_poc`

## 1. 목표

태그 PDF에서 장 제목이 표준 Heading 태그가 아니라 다음 구조의 목록 항목으로 저장된 경우에도, 근거가 충분하면 semantic XML과 Markdown에서 최상위 장 제목(`heading level=2`, Markdown `##`)으로 승격한다.

```text
List Item
├─ Label: 03
└─ List Body: Troubleshooting and Maintenance
```

프로필별 예상 장 번호나 언어별 제목 문자열은 정의하지 않는다. 판정에는 PDF에서 직접 얻은 구조, 번호 순서, 상대 글자 크기와 다국어 일관성만 사용한다.

원본 구조를 감사할 수 있도록 `raw_structure.xml`에는 PDF 태그 구조를 변경 없이 보존한다.

## 2. 확인된 표본

현재 대표 표본에서 번호형 장 제목은 다음과 같이 나타난다.

| 표본 | 언어 구성 | 언어별 번호 | 제목/본문 글자 크기 |
| --- | --- | --- | --- |
| ZC | ENG, C-FRA | 각 `01~04` | 약 16pt / 7pt |
| ZA | ENG | `01~03` | 약 16pt / 7pt |
| ZG | ENG, DEU, FRA, ITA, DUT | 각 `01~05` | 약 12pt / 6.5pt |

세 표본에서 직접 `Label`과 `List Body`를 가진 두 자리 번호 후보는 모두 실제 장 제목이었다. 다만 후보의 상위 `List`에는 다른 `List Item`이 함께 들어갈 수 있으므로 “상위 List에 항목이 하나뿐인가”는 조건으로 사용하지 않는다.

## 3. 선택한 방식

구조, 번호 순서, 상대 글자 크기를 결합한 보수적 판정을 사용한다.

- 구조만 사용하는 방식은 일반 번호 목록을 장 제목으로 오판할 수 있다.
- 구조와 순서만 사용하는 방식은 연속된 두 자리 번호 목록을 오판할 가능성이 남는다.
- 글자 크기만 사용하는 방식은 큰 경고문이나 강조문을 제목으로 오판할 수 있다.
- 세 신호를 함께 사용하면 제목 문자열과 프로필별 장 개수를 하드코딩하지 않고도 오판 가능성을 낮출 수 있다.

다국어 장 개수 일치는 개별 후보의 승격 근거가 아니라 문서 전체의 교차 검증 조건으로 사용한다.

## 4. 데이터 모델

PDF 콘텐츠 스트림을 읽을 때 텍스트 조각별로 다음 표시 정보를 함께 수집한다.

- `font_size`: PDF 텍스트 상태에서 얻은 글자 크기
- `font_name`: PDF 글꼴 리소스 또는 해석된 글꼴 이름
- `page_index`
- `mcid`
- 원문 텍스트

하나의 MCID에 여러 텍스트 조각이나 글꼴 크기가 섞인 경우, 문자 수로 가중한 글자 크기 중앙값을 그 MCID의 대표 크기로 사용한다. PDF 리소스에서 얻은 글꼴 이름은 사람이 확인할 감사 근거로 저장한다. 리소스 이름 자체에 스타일 이름이 포함될 수 있지만 정규화한 글꼴 굵기는 별도로 추론하거나 기록하지 않으며, 글꼴 이름과 굵기 모두 승격 판정에 사용하지 않는다.

`ContentFragment`에는 텍스트와 함께 표시 정보가 연결되어야 한다. XML 출력에는 판정을 재현할 수 있도록 제목 후보의 대표 글자 크기, 비교한 본문 기준 크기, 크기 비율과 승격 사유를 기록한다. 기존 소비자가 텍스트만 읽는 동작은 유지한다.

## 5. 장 번호 묶음

현재 별도 POC의 태그 트리에는 ZC와 ZG의 언어 구간이 별도 메타데이터로 저장되어 있지 않다. 이 기능에 주 프로젝트의 프로필이나 GridCell 규칙을 끌어오면 “프로필별 정의 없이 판정한다”는 목표와 프로젝트 분리 원칙이 깨진다.

따라서 번호 순서와 본문 기준 크기는 다음과 같이 자동 감지한 장 번호 묶음별로 계산한다.

- 구조 후보를 PDF 읽기 순서로 나열한다.
- `01` 후보가 나타날 때마다 새 장 번호 묶음을 시작한다.
- 그다음 `01` 직전까지의 후보와 일반 본문을 같은 묶음으로 본다.
- 후보가 한 묶음뿐이면 단일 언어 또는 단일 장 번호 구간으로 처리하고 개수 교차 검사는 적용하지 않는다.
- 후보 묶음이 둘 이상이면 각 묶음이 서로 다른 언어 구간일 가능성이 높은 것으로 보고 장 개수를 교차 검사한다.

이 방식은 실제 언어명을 추측하지 않는다. ZC와 ZG처럼 언어가 바뀔 때 장 번호가 `01`부터 다시 시작하는 구조를 이용하며, ZA는 하나의 묶음으로 처리한다. 결과 보고서에서는 근거 없는 언어명을 붙이지 않고 `series_index`로 구분한다.

## 6. 후보 탐지

다음 조건을 모두 만족하는 `List Item`만 장 제목 후보가 된다.

1. `List Item`의 직접 자식에 `Label`과 `List Body`가 각각 존재한다.
2. 정규화한 Label이 마침표나 괄호 없이 두 자리 십진수 `01~99`이다.
3. `00`, `1.`, `2.`, `(1)`, `①` 등은 제외한다.
4. `List Body`에서 비어 있지 않은 제목 텍스트를 복원할 수 있다.

제목의 길이, 단어, 문장부호는 필수 조건으로 삼지 않는다. 예를 들어 `What's in the Box?`처럼 물음표가 있는 실제 제목도 허용해야 하기 때문이다.

## 7. 번호 순서 판정

각 장 번호 묶음에서 후보를 PDF 읽기 순서대로 정렬하고 다음을 확인한다.

1. 첫 후보가 `01`이다.
2. 이후 번호가 `02`, `03`처럼 1씩 증가한다.
3. 중복과 누락이 없다.
4. 적어도 후보가 2개 이상이다.

연속 순서가 깨지면 해당 장 번호 묶음을 자동 승격하지 않고 진단에 누락 또는 중복 번호를 기록한다. 장이 하나뿐인 문서는 이번 자동 승격 범위에서 제외하고 사람이 확인하도록 한다. 이 제한은 일반 목록 오판을 줄이기 위한 보수적 안전장치다.

## 8. 상대 글자 크기 판정

절대 크기 `16pt`나 특정 글꼴 이름은 하드코딩하지 않는다. 장 번호 묶음마다 일반 본문의 대표 글자 크기를 계산하고 제목 후보와 비교한다.

### 본문 기준 크기

- 해당 장 번호 묶음의 첫 `01`부터 다음 묶음의 `01` 직전까지, semantic role이 일반 문단인 텍스트의 글자 크기를 수집한다.
- 장 제목 후보와 빈 텍스트는 기준 집합에서 제외한다. 작은 글자를 임의 기준으로 먼저 제거하지 않고 가중 중앙값이 각주나 주석의 영향을 줄이도록 한다.
- 문자 수로 가중한 중앙값을 `body_font_size`로 사용한다.

### 제목 크기

- Label과 List Body 각각의 문자 수 가중 중앙값을 계산한다.
- 둘 중 작은 값을 `heading_font_size`로 사용한다. 숫자만 크고 제목 본문은 작은 경우를 방지하기 위해서다.
- `heading_font_size / body_font_size`를 `font_size_ratio`로 계산한다.

초기 승격 기준은 다음과 같다.

```text
font_size_ratio >= 1.5
```

Label과 List Body의 대표 크기는 서로 10% 이내여야 한다. PDF 리소스 글꼴 이름은 보고서에 감사 근거로 남기지만, PDF마다 이름과 인코딩이 다를 수 있으므로 필수 조건으로 삼지 않는다. 정규화한 굵기는 별도로 추론하지 않는다.

본문 기준 크기를 계산할 자료가 부족하거나 글자 크기를 얻지 못하면 자동 승격하지 않고 `insufficient_typography_evidence` 진단을 기록한다.

## 9. 승격 결과

한 장 번호 묶음에서 구조, 연속 번호, 상대 글자 크기 조건을 모두 통과하면 각 후보를 semantic XML에서 레벨 2 Heading으로 표현하고 Markdown에서는 다음처럼 출력한다.

```markdown
## 03 Troubleshooting and Maintenance
```

현지어 제목은 `List Body`에서 추출한 원문을 그대로 사용한다. 번역, 사전, LLM 추론 또는 영문 제목 문자열과의 매칭은 수행하지 않는다.

semantic XML에는 최소한 다음 판정 근거를 남긴다.

- 원본 source role과 Label/List Body 관계
- 원래 번호와 제목
- `heading_level=2`
- `promotion_reason=numbered_chapter_structure_sequence_typography`
- `heading_font_size`
- `body_font_size`
- `font_size_ratio`
- `heading_font_names`
- `body_font_names`

## 10. 다국어 개수 교차 검증

장 번호 묶음이 둘 이상인 PDF는 승격 판정 후 묶음별 장 개수를 비교한다.

- 모든 묶음의 개수가 같으면 교차 검증을 통과한다.
- 개수가 다르면 개별 언어에서 근거가 충분한 제목 표시는 유지하되, 품질 보고서는 실패 처리한다.
- 보고서에는 `series_index`별 장 번호와 누락이 의심되는 번호를 표시한다.
- ZA처럼 장 번호 묶음이 하나인 PDF에는 이 검사를 적용하지 않으며 실패로 보지 않는다.

개수 불일치는 번역 제목을 추측하거나 누락된 장을 자동 생성하는 근거로 사용하지 않는다.

## 11. 오류 처리와 품질 게이트

다음은 자동 승격을 막는 조건이다.

- Label/List Body 직접 자식 구조 불일치
- 두 자리 번호 형식 불일치
- `01` 시작 실패, 번호 누락 또는 중복
- 제목 후보 2개 미만
- 글자 크기 정보 부족
- 제목/본문 크기 비율 1.5 미만
- Label과 List Body 크기 차이 10% 초과

다국어 장 개수 불일치는 이미 근거가 충분한 개별 제목 표시를 되돌리지는 않지만, 문서의 hard quality gate를 실패시킨다. 모든 실패에는 언어, 페이지, MCID, Label과 계산값을 포함한 진단을 남긴다.

## 12. 테스트 기준

### 단위 테스트

- `01`, `02`, `10`은 후보가 되고 `00`, `1.`, `(1)`, `①`은 제외된다.
- Label/List Body가 직접 자식이 아닐 때 제외된다.
- `01, 02, 03`은 통과하고 `01, 03`, `01, 02, 02`는 실패한다.
- 제목 16pt/본문 7pt와 제목 12pt/본문 6.5pt는 통과한다.
- 제목 9pt/본문 7pt는 실패한다.
- Label 16pt/List Body 7pt처럼 크기가 다른 경우 실패한다.
- 글자 크기가 없는 경우 자동 승격하지 않고 진단을 남긴다.

### 통합 테스트

- ZC: ENG와 C-FRA에서 각각 `01~04`가 `##`로 출력되고 개수 검증을 통과한다.
- ZA: ENG에서 `01~03`이 `##`로 출력되며 단일 언어 개수 검증은 적용하지 않는다.
- ZG: BOOK 언어 구간별로 ENG/DEU/FRA/ITA/DUT 각각 `01~05`가 `##`로 출력된다.
- 일반 `1.`, `2.` 목록은 기존 목록 표현을 유지한다.
- `raw_structure.xml`의 원본 List 구조는 변경되지 않는다.
- 기존 public CLI와 기존 XML/Markdown 생성 계약은 유지된다.

### 회귀 테스트

- 기존 전체 POC 테스트를 실행한다.
- ZC, ZA, ZG 결과에서 기존 본문·목록·내비게이션 텍스트가 손실되지 않았는지 확인한다.
- 프로젝트 표준에 따라 관련 집중 테스트와 `python -m compileall src tests scripts apps`를 실행한다.

## 13. 범위 제외

이번 변경에는 다음을 포함하지 않는다.

- 프로필별 예상 장 번호 또는 장 개수 정의
- 언어별 제목 하드코딩
- 제목 번역 또는 의미 기반 매칭
- 누락된 제목의 자동 생성
- 일반적인 모든 시각적 Heading 추론
- 기존 주 프로젝트의 콘텐츠 추출 규칙 변경
