# 시맨틱 마크다운 가독성 개선 설계

**작성일:** 2026-09-06
**대상 프로젝트:** `samples/tagged_pdf_xml_poc`
**상태:** 구현 계획 작성 승인 완료

## 목적

PDF에서 확인된 의미 구조는 바꾸지 않으면서 `semantic_document.md`를 사람이 읽기 쉽게 개선한다. 하나의 원본 구조 단위 안에 있는 문장 경계를 표시하고, 문장 안의 작은 아이콘과 일반 그림을 구분하며, `※` 같은 의미 있는 원본 목록 라벨이 누락되지 않게 한다.

## 작업 범위

### 포함

- 기존 의미 구조를 유지한 채 대상 문단, 목록 본문, 표 셀 문단 안에 표시 전용 문장 줄바꿈을 넣는다.
- URL, 이메일 주소, 소수, 버전 문자열, 약어처럼 마침표를 포함하는 문자열이 잘못 나뉘지 않게 보호한다.
- 문장 안에 포함된 작은 `figure`는 구조적 위치와 상대적인 크기로 인라인 아이콘임을 확인할 수 있을 때 `[아이콘]`으로 표시한다.
- 문장 밖에 있거나 크기가 크거나 판단이 불확실한 빈 `figure`는 `[그림: 텍스트 없음]`으로 유지한다.
- 의미 있는 원본 각주 라벨 `※`를 Markdown에서 불필요한 불릿 없이 `※ 설명`으로 보존한다.
- `UK ※ 2025-10-31`처럼 문장 안의 `※` 참조 기호 주변 간격을 보존한다.
- 바이어와 언어에 관계없이 같은 구조적 근거가 발견되면 공통 규칙을 적용한다.
- ZG를 다국어 BOOK 양성 검증 샘플로, ZC를 2언어 시트 대조군으로, KR을 한국어 단일 언어 대조군으로 사용한다. 기존 ZA/XY 단위 테스트는 유지하지만 이번 변경에서는 해당 PDF를 다시 생성하거나 사람이 검수하지 않는다.

### 제외

- 홈이나 설정처럼 아이콘 이름을 판별하는 기능
- OCR 또는 시각적 아이콘 인식
- 아이콘 카탈로그 또는 이미지 유사도 비교
- 원본 목록 항목 하나를 여러 목록 항목으로 분리하는 변경
- 원본 표 셀 하나를 여러 행이나 셀로 분리하는 변경
- PDF 원문이나 기존 번호 헤딩, RF 줄바꿈, 소제목, 적합성 선언 서식 규칙 변경
- 편집기의 구문 강조 색상만 바꾸기 위해 대괄호 모델명에 이스케이프 문자를 추가하는 변경

## ZG 검토 결과에서 확인한 근거

### 문장 표시

`Veillez à brancher correctement...`로 시작하는 프랑스어 안전 문구는 태그 구조상 하나의 `list_item > list_body`이며 그 안에 문장 네 개가 들어 있다. Raw XML에는 지면 너비 때문에 접힌 물리적 행이 남아 있지만, 그 위치는 문장 경계와 일치하지 않는다.

`Diese Kennzeichnung auf der Batterie...`로 시작하는 독일어 배터리 폐기 본문은 표 셀이 아니다. `Document > Article > Story` 아래 경로 `(0, 0, 12, 7)`의 인라인 leaf `paragraph` 하나다. 바로 앞 형제 `(0, 0, 12, 6)`은 의미 있는 자식으로 표 하나만 가진 wrapper 문단이며, 그 표 안의 `(0, 0, 12, 6, 0, 0, 1, 0)`에는 검증된 소제목 `Ordnungsgemäße Entsorgung der Batterien in diesem Gerät`가 있다. 이어지는 본문 문단 하나에 물리적 줄 접힘과 일치하지 않는 문장 세 개가 들어 있다.

따라서 물리적 fragment 경계는 원본 추적 근거로만 사용하고 문장 경계로 사용하지 않는다. 표시용 문장 줄바꿈은 합쳐진 가시 텍스트를 대상으로 보수적으로 판별해야 한다.

### 각주 라벨

`Cette adresse n'est pas...`로 시작하는 설명 행의 태그 구조는 다음과 같다.

```text
list_item
  label: ※
  list_body: Cette adresse n'est pas...
```

현재 Markdown 작성기는 `Ł`, `Œ`처럼 깨진 불릿 글리프를 숨기기 위해 순서형 라벨이 아닌 임의의 라벨을 `-`로 교체한다. 이 규칙 때문에 의미 있는 `※` 라벨도 함께 사라진다. 수정된 규칙은 의미 있는 각주 기호와 일반 또는 깨진 불릿 글리프를 구분해야 한다.

### 모델 라벨 색상

대괄호로 둘러싸인 모델 라벨 다섯 개는 PDF에서 모두 같은 서식을 사용한다. 글꼴은 `SamsungOne-600`, 크기는 `6.5`, 색상은 RGB `(35, 31, 32)`이며 source role도 같다. Markdown 작성기 역시 다섯 행 모두 같은 일반 대괄호 문법으로 출력한다. 편집기가 앞의 두 행만 다르게 표시하는 이유는 대괄호 안에 공백이 없어 링크와 비슷한 Markdown 토큰으로 구문 분석하기 때문이다. 이는 원본 서식 차이가 아니므로 추출 로직을 변경할 필요가 없다.

## 설계 결정

### 1. 기존 컨테이너를 유지하고 표시 전용 문장 경계만 추가한다

문장 서식 처리로 새로운 `list_item`, `table_row`, `table_cell`, 의미 문단을 만들면 안 된다. Markdown에서는 이어지는 문장을 새 줄에 표시할 수 있지만, 모든 연속 행은 원래 source 단위에 계속 속해야 한다.

기존 목록 본문과 표 셀 문단 범위 외의 일반 section 문단은 다음의 좁은 공통 규칙을 모두 만족할 때만 대상이 된다.

1. 표 안에 중첩된 검증 완료 `document.subtitle_hints` 대상에서 시작한다.
2. 해당 표가 wrapper 문단의 유일한 의미 있는 자식이어야 한다.
3. wrapper 문단의 바로 다음 형제가 비어 있지 않은 인라인 leaf 문단이어야 한다.
4. 보수적 문장 판별기가 실제 경계를 찾은 경우에만 힌트를 만든다.
5. 같은 본문 경로는 한 번만 처리한다.

바이어, 언어, 제목, 본문 문자열은 판별에 사용하지 않는다. 임의의 section 문단이나 구조가 잘못되었거나 서로 떨어져 있거나 여러 의미 있는 자식을 가진 wrapper에는 적용하지 않는다. 검토한 샘플에서는 ZG 본문 문단 7개에 break offset 11개만 추가하고 ZC와 KR에는 하나도 추가하지 않는다.

문장 판별기는 하나의 대상 시맨틱 텍스트 컨테이너 안에 있는 가시 텍스트만 처리한다. 종결 문장부호 뒤에 다음 문장을 시작할 수 있는 공백이 아닌 문자가 있을 때 문장 경계 후보를 만든다. 다음과 같이 보호 대상 문자열에 포함된 마침표에서는 나누지 않는다.

- URL과 이메일 주소
- 소수 값
- `V2.2.3` 같은 점으로 구분된 버전과 표준
- 이니셜과 짧은 약어
- 말줄임표
- 모델 코드와 파일 형태의 문자열

경계가 불확실하면 줄바꿈을 만들지 않는다. 이미 존재하는 원본 작성 줄바꿈을 우선하며 중복해서 추가하지 않는다.

Markdown에는 명시적인 `<br>`을 사용하고 필요한 경우 이어지는 행을 들여쓴다. 눈에 보이지 않는 줄 끝 공백보다 Markdown 뷰어 간 동작이 안정적이며, 하나의 불릿이나 셀이 여러 줄에 걸쳐 있다는 점도 유지할 수 있다.

### 2. 이름을 판별하지 않고 인라인 아이콘만 분류한다

다음 조건을 모두 만족하는 `figure`만 `[아이콘]` 후보가 된다.

- 그림 또는 표 셀 안의 유일한 블록이 아니라 문단이나 목록 본문의 인라인 자식 사이에 있다.
- 같은 텍스트 흐름에서 바로 앞이나 뒤에 가시 텍스트가 있다.
- 페이지와 BBox 근거가 존재한다.
- 주변에서 확인된 텍스트 행에 비해 높이와 너비가 작고 독립된 삽화처럼 보이지 않는다.

상대적 크기 임계값은 코드에 고정하고 양성·음성 예시로 테스트한다. 바이어나 언어별로 값을 바꾸지 않는다. 대체 텍스트가 있으면 근거로 보존할 수 있지만 아이콘 이름으로 출력하지 않는다.

조건을 만족하면 `[아이콘]`으로 표시한다. 독립된 그림, 큰 그림, 근거가 부족한 그림, 판단이 모호한 그림은 `[그림: 텍스트 없음]`으로 유지한다. 잘못된 아이콘 판정보다 일반 그림으로 남기는 것을 우선하는 보수적인 정책이다.

### 3. 의미 있는 각주 기호를 목록 불릿과 별도로 보존한다

Markdown 목록 라벨 판별기는 라벨을 세 종류로 구분한다.

1. 기존 순서형 목록 규칙으로 출력하는 원본 순서형 라벨
2. 불릿 `-` 없이 본문 앞에 원문 그대로 표시하는 `※` 같은 검증된 각주 기호
3. 기존의 안전한 구조 불릿 `-`를 사용하는 일반 불릿, 깨진 글리프, 임의 라벨

이 분류는 기호를 기준으로 하며 언어나 바이어별 규칙이 아니다. Markdown 표시가 목록 기호 대신 `※`로 시작하더라도 본문은 원래 시맨틱 `list_item`에 계속 연결된다.

인라인 간격 정규화는 서로 붙어 버린 fragment 사이의 `※` 주변에 가시적인 구분 공백을 보존한다. 다른 문장부호와 모델 코드 문자열은 바꾸지 않는다.

### 4. 모든 판별 결과를 추적할 수 있게 한다

문장과 인라인 아이콘 표시 판별은 Markdown 출력 전에 수행하며 검증된 Semantic XML 표시 근거로 노출한다. Markdown 작성기는 이 근거만 사용하며 PDF나 파일명을 보고 추측하지 않는다.

근거에는 대상 structure path, 표시 역할과 사유, 원본 페이지, 가능한 경우 MCID와 object reference, 아이콘 판단에 사용한 geometry를 포함한다. Raw XML은 변경하지 않는다.

## 데이터 흐름

1. 태그 PDF 추출 단계에서 raw 구조, fragment, MCID, object reference, 페이지, BBox, 원문을 보존한다.
2. Semantic XML 생성 단계에서 원본 계층과 자식 순서를 유지한다.
3. 공통 가독성 분석 단계에서 보수적인 문장 경계, 대상 인라인 아이콘, 의미 있는 각주 라벨을 판별한다.
4. 표시 근거 검증 단계에서 서로 충돌하거나 겹치거나 구조상 허용되지 않는 판별을 거부한다.
5. Semantic XML에는 검증된 표시 근거를 기록하되 Raw XML은 변경하지 않는다.
6. Markdown 작성기는 Semantic XML을 기준으로 문장 연속 행, `[아이콘]`, 일반 그림 표시, `※` 라벨을 출력한다.

## 실패 처리

- 문장부호가 모호하면 한 줄로 유지한다.
- 그림의 geometry나 주변 텍스트가 없으면 일반 그림으로 유지한다.
- 표시 근거가 서로 충돌하면 출력 파일을 게시하기 전에 검증 단계에서 실패시킨다.
- 지원하지 않는 목록 라벨에는 기존의 안전한 구조 불릿을 계속 사용한다.
- 원문이 사라지거나 중복 출력되면 안 된다.
- 가독성 개선 처리에 실패하더라도 기존 출력 묶음을 손상시키거나 일부만 교체하면 안 된다.

## 검증

### 집중 단위 테스트

- 프랑스어 문장 네 개가 하나의 목록 항목을 유지하면서 화면상 네 줄로 표시되는지 확인한다.
- 독일어 배터리 폐기 문장 세 개가 검증된 소제목/표 wrapper 바로 다음의 leaf 문단 하나를 유지하면서 화면상 세 줄로 표시되는지 확인한다.
- URL, 이메일, 소수, 표준, 버전, 약어, 말줄임표가 잘못 분리되지 않는지 확인한다.
- 기존 원본 RF 줄바꿈이 제거되거나 중복되지 않는지 확인한다.
- 텍스트 fragment 사이의 작은 그림이 `[아이콘]`으로 표시되는지 확인한다.
- 독립된 그림, 큰 그림, 불확실한 그림, geometry가 없는 그림이 `[그림: 텍스트 없음]`으로 유지되는지 확인한다.
- `※` 목록 라벨은 `※ 설명`으로 한 번만 출력하고 `Ł`, `Œ`, 일반 불릿은 기존처럼 숨기거나 구조 불릿으로 정규화하는지 확인한다.
- 인라인 `※` 참조 기호 주변에 읽을 수 있는 간격이 남는지 확인한다.
- Semantic XML에 검증된 근거가 들어가고 Raw XML에는 표시 속성이 전혀 들어가지 않는지 확인한다.

### 샘플 회귀검사

- ZG를 다시 생성하고 ENG, DEU, FRA, ITA, DUT 예시를 확인한다.
- ZC와 KR을 다시 생성하여 잘못된 아이콘 승격이나 구조 변경이 없는지 확인한다. 기존 ZA/XY 단위 테스트는 유지하되 신규 실물 PDF 검수 실행은 하지 않는다.
- 기존 번호 헤딩, 소제목, RF 줄바꿈, 적합성 선언 계층, 복잡한 표, 출력 묶음 안전성 테스트가 계속 통과해야 한다.
- 전체 POC 테스트와 `AGENTS.md`가 요구하는 저장소 컴파일 검사를 실행한다.

## 완료 결과물

ZG, ZC, KR 검토용 출력 묶음을 다시 생성한다. 세 개의 `semantic_document.md` 경로를 제공하고, 사람이 직접 검토할 수 있도록 문장 네 개가 들어 있는 ZG 불릿, 문장 세 개가 들어 있는 검증된 소제목/표 wrapper 바로 다음 leaf 문단, 인라인 아이콘, `※` 각주가 있는 정확한 행을 안내한다.
